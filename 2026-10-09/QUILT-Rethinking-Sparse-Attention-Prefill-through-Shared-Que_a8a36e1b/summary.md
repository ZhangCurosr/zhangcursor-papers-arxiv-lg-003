# 论文速读：QUILT: Rethinking Sparse-Attention Prefill through Shared Query Execution

## 一句话总结
本文提出 **QUILT**，一种工作负载感知的稀疏注意力预填充执行机制，通过基于查询组的协同执行显式利用相邻查询间的高度重叠 KV 条目，将不规则集合运算转化为数据并行原语（SCSD），并结合级联共享与瓦片感知裁剪，在保持精度的同时将稀疏注意力 Kernel 延迟降低最高 **55.1%**，TTFT 延迟降低最高 **36.8%**。

## 研究问题与动机
- **现有稀疏注意力 Kernel 的“工作负载无关”缺陷**：主流实现（如 OPS-Transformer）采用查询并行执行，每个 Query 独立加载、反量化并处理其 Top-$k$ KV 条目，完全忽略相邻查询间稀疏工作负载的强相关性。
- **相邻查询存在高度重叠的 KV 选择**：对 GLM-5.3 的 Profiling 显示，在 Qasper 和 GovReport 数据集上，相邻两个 Query 的 KV 重叠率普遍超过 **85.91%**（第一层甚至超过 **90.03%**），导致大量重复的 HBM→片上内存搬运与反量化计算。
- **冗余开销占据主导**：在 Ascend 910C NPU 上的实测表明，KV 加载与反量化共同构成现有稀疏注意力 Kernel 执行时间的最大部分，存在显著优化空间。
- **跨查询重用到性能增益的转化挑战**：直接进行集合分解会引入额外开销；固定组大小无法适配不同层/数据集/粒度下的异构共享模式；共享段与硬件 Tile 边界不对齐会导致尾部 Tile 利用率低下。

## 核心贡献（创新点）
1. **提出工作负载感知的组查询执行框架（QUILT）**：打破传统查询并行范式，显式利用跨查询 KV 重叠，使共享 KV 仅加载/反量化一次并在组内复用。
   - **区别**：不同于仅优化单查询访问的稀疏注意力工作（如 MInference、FlexPrefill），本文从**系统执行层**挖掘相邻查询间的相关性，与现有稀疏索引生成方法正交。
2. **设计 Shift-and-Compare Set Decomposition (SCSD) 算法**：将不规则集合交并差运算转化为排序、移位、比较和布尔掩码等规则数据并行原语，避免标量遍历与分支。
   - **区别**：相比朴素 Torch 集合实现（慢 20×+），SCSD 将集合分解开销降低 **96%+**，并可通过流水线技术与注意力计算重叠。
3. **引入级联共享（Cascaded Sharing）机制**：从大到小递归分解查询组，在多个粒度层级上逐层提取共享 KV，而非固定单一组大小。
   - **区别**：固定组大小（如 2/4/8）无法同时捕获粗粒度全局共享与细粒度子组共享，级联策略可实现接近理论最优的数据复用。
4. **提出瓦片感知执行与重要性感知裁剪**：根据 Tile 利用率阈值决定是否将尾部下推至下一级共享，并在最终查询专属层基于索引器分数剪枝低重要性残余条目。
   - **区别**：唯一近似步骤仅移除最低重要性残差 KV，Cosine Similarity 实验表明其对注意力输出的扰动极小（头部均值相似度 **1.0000**）。

## 方法详解
- **SCSD 核心流程**：对两个 Top-$k$ 索引列表 $A$ 和 $B$，拼接后联合排序得到 $(C, T)$；通过右移 $C_r$ 和左移 $C_l$ 并与 $C$ 逐元素比较，构造掩码 $D=(C=C_r)$、$F=(C=C_l)$；共享交集 $E=C[D]$，查询专属项 $G=\neg(D\lor F)$ 并按来源标签分离。全部操作为规则向量原语，可充分并行。
- **流水线执行**：现代加速器中矩阵引擎（QK/PV）与向量引擎可并发。将 SCSD 拆解为多个细粒度阶段，嵌入注意力 Kernel 的向量空闲时槽，使集合分解与 QK/PV 计算重叠，临界路径额外开销近乎为零。
- **级联共享**：默认起始组大小 8，先提取 8 个查询的全局交集 KV 并联合处理；剩余条目递归划分为更小组（4→2→1），逐层提取共享子集；最终残差作为查询专属 KV 独立处理。
- **瓦片感知裁剪**：设 Tile 大小 $T$、阈值 $\tau=50\%$。对共享段尾部剩余 $r$ 个 KV，若 $r\geq\tau T$ 则 Padding 补齐当前 Tile；否则下推至下一级与更细粒度工作合并。在最终查询专属层，由于残差集中在 Top-$k$ 尾部（低重要性），按索引器分数保留最高 $q_iT$ 个条目，裁剪最低 $r_i$ 个以消除低利用率 Tile。

## 实验与结果
- **平台**：16× Ascend 910C NPU（64 GB HBM），CANN 9.1.0，XYServe 推理引擎。
- **模型与数据集**：GLM-5.3、DeepSeek-3.2（均含原生稀疏注意力 DSA/Top-2048），LongBench 21 个长上下文任务（QA、Summarization、Code Generation 等）。
- **基线**：OPS-Transformer 优化稀疏注意力 Kernel（当前 Ascend 平台最优实现）。
- **精度保持**：21 个 LongBench 数据集上，QUILT 与基线平均绝对分差仅 **0.42**（GLM-5.3）/ **0.75**（DeepSeek-3.2），相对误差 **0.90%–2.01%**，可忽略。
- **Kernel 延迟**：GLM-5.3 在 TP 下平均降低 **53.8%**（最高 **55.1%**，GovReport），SP 下平均 **43.4%**；DeepSeek-3.2 在 TP 下平均 **28.7%**，SP 下 **17.1%**。
- **KV 处理量**：GLM-5.3 平均减少 **54.7%**（最高 **55.9%**），DeepSeek-3.2 平均减少 **30.4%**。
- **TTFT 延迟**：GLM-5.3 在 TP 下平均降低 **35.6%**（最高 **36.8%**），SP 下 **10.4%**；DeepSeek-3.2 在 TP 下 **23.0%**，SP 下 **3.4%**。
- **消融验证**：Naive 集合实现比基线慢 **21–33×**；SCSD 降速 **96%+**；流水线再降 **23–46%**；级联共享较固定组 2/4/8 进一步减少 **11–31%** 处理的 KV 数；瓦片裁剪带来额外 **14–24%** Kernel 延迟下降。

## 相关工作脉络
1. **训练无关稀疏注意力**（MInference、FlexPrefill、XAttention）：在推理时通过代理计算或块评分动态选取重要 KV，**关注“选哪些”**；QUILT 与其正交，可直接叠加于其输出结果之上。
2. **原生稀疏注意力**（NSA、DeepSeek DSA、GLM-5、Hunyuan-4）：将轻量级索引器嵌入模型训练；QUILT 不修改索引生成逻辑，**透明作用于最终稀疏工作负载**。
3. **解码阶段稀疏 KV 缓存**（H₂O、StreamingLLM、SnapKV、Quest、InfLLM）：利用自回归解码步间的时间局部性压缩 KV Cache；QUILT 针对**预填充阶段并发 Query 间的空间重叠**。
4. **硬件高效注意力 Kernel**（FlashAttention、FlashAttention-2/3、FlashInfer）：通过 Tile 化、在线 Softmax、异步流水等提升矩阵计算利用率；QUILT 进一步挖掘**稀疏模式下跨查询的 KV 复用**，填补现有 Kernel 未覆盖的冗余点。
5. **稀疏 Prefill 系统优化**（FlashPrefill）：专注硬件感知的稀疏模式发现；QUILT 从**查询组执行**角度切入，两者可互补。

## 局限性与未来方向
- **固定默认组大小（8）可能非全局最优**：不同模型层、数据集和并行度下最佳共享粒度存在差异，动态自适应组选择尚未充分探索。
- **重要性感知裁剪为唯一近似步骤**：虽精度损失可忽略，但在极端长上下文或对尾部信息敏感的任务中仍需谨慎评估。
- **仅针对预填充阶段**：解码阶段的跨步稀疏重叠未被利用，未来可与解码侧稀疏 KV 缓存技术结合。
- **硬件适配验证局限于 Ascend NPU**：虽设计基于通用加速器特征（矩阵/向量异构单元、Tile 执行），但在 GPU 等其他架构上的具体实现性能待进一步验证。

## 研究启发与可借鉴点
1. **工作负载相关性的系统性挖掘**：在稀疏访问场景下，相邻请求/Query 间的重叠往往被低估； profiling 驱动发现此类规律可打开新的优化维度。
2. **不规则运算的规则化转换**：SCSD 将集合交并差转化为排序+移位+比较+掩码，是“把控制流密集型操作转为数据并行原语”的典范，可迁移至其他动态调度场景（如动态路由、稀疏 MoE）。
3. **流水线隐藏元数据开销**：将辅助计算（集合分解、索引重建）拆分并嵌入主计算流水线的空闲槽，是典型“用计算换时间”的 trick，适用于各类带预处理阶段的 Kernel。
4. **多级粒度共享与自适应裁剪**：级联共享 + 瓦片感知阈值 + 重要性裁剪的组合策略，为“在精确性与硬件利用率间权衡”提供了结构化思路。
5. **端到端指标与 Kernel 指标联动验证**：同时报告 Kernel 延迟、KV 处理量、TTFT 和精度四项指标，完整刻画优化收益，可作为系统论文评估模板。

## 关键术语表
- **Sparse Attention（稀疏注意力）**：每个 Query 仅 attending 到 Top-$k$ 个重要 KV 条目，而非全量序列，以降低预填充阶段的计算与内存开销。
- **KV Cache（键值缓存）**：在 LLM 推理中缓存已处理 Token 的 Key 和 Value 向量，避免重复计算；稀疏注意力常配合低精度存储与按需反量化。
- **Top-$k$ Indexer（Top-k 索引器）**：轻量级可学习或启发式模块，用于为每个 Query 动态筛选出最重要的 $k$ 个 KV 位置。
- **SCSD（Shift-and-Compare Set Decomposition）**：将两个有序索引列表的交集/差集运算转化为排序、移位、相等比较和布尔掩码的数据并行原语序列。
- **Cascaded Sharing（级联共享）**：从大查询组开始递归提取各粒度共享 KV，逐层下推残差，实现多级重用捕获。
- **Tile-aware Clipping（瓦片感知裁剪）**：根据硬件 Tile 大小与利用率阈值，决定是否将尾部 KV 下推或 Padding；最终层基于重要性分数剪枝低价值残差。
- **TTFT（Time-to-First-Token）**：从输入到模型生成第一个输出 Token 的延迟，直接反映用户感知的预填充性能。
- **Tensor/Sequence Parallelism（张量/序列并行）**：TP 沿模型维度切分计算，SP 沿序列长度切分；本文在两配置下均验证了 QUILT 的有效性。
