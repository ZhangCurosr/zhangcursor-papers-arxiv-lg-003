# 论文速读：YANchor-4B: Effective Long-Horizon Reasoning in O(N) Time with O(1) Memory

## 一句话总结
YANchor-4B 是一种基于 Qwen3.5-4B 的通用循环架构模型，通过引入独立记忆锚点（ANchors）结合循环状态与局部注意力，在 O(N) 生成时间与 O(1) 历史状态内存约束下实现高效长程推理，在 AIME 数学竞赛等困难任务上大幅超越同等规模线性时间基线。

## 研究问题与动机
1. **长程推理的存储与计算瓶颈**：完全历史注意力随生成长度增长带来递增缓存占用与计算开销，扩展生成成本高昂。
2. **循环压缩的信息丢失**：纯循环/状态空间模型用固定维度摘要压缩历史，多次更新后难以保持精确细节与远端关联。
3. **局部窗口的距离盲区**：固定窗口注意力保留近期细节，但超出窗口的远端关键信息无法被访问。
4. **缺乏有界状态下的有效长程能力**：现有线性时间、常数状态模型在复杂多步推理中表现不足，尤其在高难度数学与长轨迹场景。

## 核心贡献（创新点）
1. **三层互补历史记录机制**：将循环状态（GDN）、局部注意力（SWA，窗口 1024）与独立记忆模块组合，分别承担压缩上下文、近期细节与远端精确检索，本质区别于仅依赖单一压缩路径的 RWKV/Mamba 类模型。
2. **基于优先级的独立记忆写入与保留**：每个 KV 组独立维护 Top-1024 记忆锚点，按 256-token 块进行候选聚合与保留决策，使关键信息可在离开局部窗口后仍被长期、可寻址检索。
3. **分组查询检索 + 零日志门控设计**：采用 grouped-query attention 与分母含单位项的归一化读取，使空记忆时输出中性、低匹配记录被自动弱化，区别于标准 softmax 全注意力的存储压力。
4. **四阶段训练管线（M0→R→S→RLVR）**：依次完成记忆模块适配、主网络联合适配、监督微调与可验证奖励强化，最终在 4.58B 参数下实现数学推理与通用能力的显著提升。

## 方法详解
- **架构组织**：32 层按 `[GDN, GDN, GDN, SWA_1024 ‖ Memory] × 8` 排列，共 24 个 GDN 层 + 8 个 SWA+Memory 层。
- **组合前向**：`z_t = h_t + SWA(Norm_local(h_t)) + Mem(h_t, M_t)`，再经 MLP 残差输出。
- **独立写入**：`w_t = u_t + W_down[SiLU(W_gate u_t) ⊙ W_up u_t]`，通过独立投影得到 K/V；查询由 `u_t` 投影，写入与检索路径解耦。
- ** Admission 网络**：`a_t = W_{a,2} SiLU(W_{a,1} u_t)` 输出每组 4 维得分，仅使用写入时可用的信息。
- **块级保留**：新记录以 256-token 块累积，块边界处与已提交记忆合并，每组独立选出 Top-1024 持久保留。
- **分组查询读取**：每记忆模块 16 个查询头、4 个 KV 组、维度 d=256；读取公式分母含单位项（零日志/零值项），使未命中时输出中性并允许注意力权重外推。
- **查询门控**：`g_{t,h} = tanh(s_h) · 2σ((q̄_{t,h}^T b_h)/√d + c_h)`，控制各头对残差流的贡献。
- **复杂度**：每 token 更新固定维度循环状态、读取最多 W 局部位置与 K 记忆记录，总自回归工作为 O(N)，历史状态 O(1)。
- **内存开销**：文本模型 4.58B 参数，其中独立记忆 372M；每序列 K/V 状态 40 MiB（BF16），在 80GB H100 上可驻留 512 条独立长序列。

## 实验与结果
- **数学推理（线性时间、常数状态对比）**：AIME 2024–2026 均值 pass@1 为 82.93%，HMMT 2026年2月为 63.64%，MATH-500 为 97.49%；最强同规模基线 RWKV-7 G1j 13.3B 在 AIME 上仅 18.89%。
- **跨架构对比**：24 基准均值 78.64，领先最强常数状态基线（56.29）+22.35 分；在 MMLU-Pro、HumanEval、MBPP、IFBench 等超过同规模 Qwen3.5-4B。
- **长推理轨迹**：AIME 平均输出 18,000–25,000 token，HMMT 约 30,189 token；较 Qwen3.5-4B 少用 43–47% token 且保留 96.31% 三年均值准确率。
- **长程记忆能力**：远程信息检索查询准确率 94.14%；关闭记忆路径降至 0.39%。变量绑定仍为最难子任务（53.13%）。
- **VL 能力**：MMBench EN/CN、POPE、MME、ChartQA、AI2D 六基准均值 84.94%。
- **推理吞吐与显存**：单 H100 128K 输入/128K 输出 decode 速率约 213 tok/s；端到端吞吐为 Qwen3.5-4B 的 4.12–6.58 倍、Gemma 4 E4B 的 3.25–5.66 倍；batch=512 时峰值显存约 67 GiB，上下文从 512 增至 65536 时历史缓存稳定在 48.90 GiB。

## 相关工作脉络
1. **RWKV-7 / ARWKV-R1 / AHN-GDN**：同类线性时间、常数状态模型，但依赖纯循环或仅局部窗口，缺少独立、可寻址的记忆锚点结构。
2. **Mamba / xLSTM / RecurrentGemma**：以固定维度状态表征历史，信息保留依赖状态演化，难以精确保留远端精确片段。
3. **RADLADS**：将预训练能力蒸馏到线性注意力解码器，属于“转换”路线；YANchor 通过“独立记忆写入-保留-读取”显式路径直接学习长程访问。
4. **HOLA / Artificial Hippocampus Networks**：探索有界精确存储以缓解循环遗忘；本文改进为分组保留、块级合并与查询条件门控的端到端可微方案。
5. **PromptCoT-Mamba / Super Apriel**：侧重推理效率权衡或统一检查点；本文提供数学竞赛长轨迹与 VL 的统一评估，强调能力与吞吐并行的工程收益。
6. **全注意力 Transformer（Qwen3.5 / MiniCPM / Gemma 系列）**：作为全局注意力参考，展示显存随上下文线性增长的代价及批量吞吐瓶颈。

## 局限性与未来方向
- **变量绑定仍是短板**：跨文档组合与变量关联的多跳绑定准确率（约 53%）显著低于精确检索与状态更新解读（87–90%），反映记忆锚点在联合可访问性上的不足。
- **块级保留带来检索延迟**：以 256-token 为粒度进行写入与选中，极端细粒度重要片段可能在块内被稀释，未来需更灵活的连续保留策略。
- **对比基线以 1.5B–14B 为主**：在更大规模（≥14B）线性时间模型上的优势幅度未系统展开，上限仍有待验证。
- **长上下文预填充与调度**：当前端到端吞吐测试侧重固定长度生成，动态交互场景下的首 token 延迟与调度优化未充分报告。
- **多模态扩展有限**：VL 结果表明可用，但未见深度跨模态长程推理（如超长文档图问答）的系统评估。

## 研究启发与可借鉴点
1. **读写路径解耦设计**：写入用独立残差变换构建存储表示，查询用归一化向量与部分 RoPE，便于分别优化保留质量与检索精度，可迁移到任务型记忆增强 RNN/SSM。
2. **零日志门控读取**：在分母引入单位项使空记忆输出中性并允许低匹配衰减，可作为通用注意力归一化改进，降低稀疏记忆下的噪声干扰。
3. **块级 Top-K 保留 + 独立分组**：将序列切块并在每组独立竞争保留位，兼顾写入局部性与组间多样性，适用于多专家记忆或多租户场景。
4. **训练流水线分层**：M0 专训记忆、R 联合训练、S 监督微调、RLVR 结局导向强化，该节奏适合“先适配组件、再整合能力、后优化输出分布”的迁移范式。
5. **工程侧固定容量驻留**：40 MiB/序列的明确预算与 H100 上 batch=512 高并发驻留，提示在有界状态模型上可直接面向批调度做显存规划，值得在推理服务中复用。

## 关键术语表
**Gated DeltaNet (GDN)**：具有门控更新的循环状态空间层，以固定维度矩阵压缩历史，提供 O(N) 生成能力。
**SWA (Sliding Window Attention)**：固定大小为 1024 的局部注意力窗口，保留近期 token 间的精确交互。
**Memory Anchor**：独立记忆模块中按优先级保留的可寻址键值记录，用于后续长期检索。
**Grouped-Query Attention (GQA) for Memory**：多查询头共享少数 KV 组的读取机制，降低存储与计算开销。
**Admission Network**：在小维度上输出每组得分的网络，决定哪些新记录进入持久记忆。
**RLVR (Reinforcement Learning with Verifiable Rewards)**：基于答案正确性等可验证信号的策略优化阶段，用于收尾改进输出质量。
**Pass@K**：对同一问题生成 K 次独立回答并计算至少一次正确的比例，本文常用 pass@1。
**Bounded-state inference**：历史状态容量不随序列长度增长的推理模式，保障 O(1) 内存与稳定吞吐。
