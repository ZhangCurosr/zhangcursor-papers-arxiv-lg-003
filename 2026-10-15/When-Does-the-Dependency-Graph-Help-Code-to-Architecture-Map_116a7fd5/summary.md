# 论文速读：When-Does-the-Dependency-Graph-Help-Code-to-Architecture-Map

## 一句话总结
本文将代码到架构映射（C2A mapping）建模为基于多关系有向依赖图的半监督节点分类任务，通过迭代自训练将少量人工标注扩展至全量文件。在10个开源Java/C++系统上的百次重复实验表明，GAT整体表现最优，且在大规模系统中依赖图带来的提升显著；同时揭示了图的连通性、同配性决定图结构有效性的边界，并指出部分模型排名对训练随机种子敏感。

## 研究问题与动机
- **架构漂移与维护成本**：代码实现偏离预期模块划分会产生架构技术债，而静态架构一致性检查依赖准确的代码-架构映射，但手动维护映射成本高且常缺失或不完整。
- **现有方法未显式建模拓扑**：传统吸引力函数与朴素贝叶斯方法将依赖关系扁平化为节点特征，未利用代码库的实际图结构；检索式方法（如InMap）依赖自然语言描述且偏交互式。
- **前期GNN研究缺乏隔离对照**：作者团队的GCN预研仅覆盖Java中等规模系统，未对比无图基线，无法回答“观察到的性能提升究竟来自图结构还是更大模型容量”。
- **任务特性差异被忽视**：架构恢复（模块集未知）与架构映射（模块集已给定）的评估设定不同，后者可利用已知GT进行半监督自训练，但缺乏系统的超参与随机性分析。

## 核心贡献（创新点）
1. **提出控制变量的半监督自训练映射框架**：GCN、GAT与MLP共享完全相同的节点特征、分类头与自训练循环，首次在该任务中隔离出依赖图相对于纯文本特征的贡献。
2. **系统性对比多关系GNN与无图基线**：将依赖图建模为异构图（每类关系独立邻接矩阵与变换），与仅依赖标识符/路径的MLP直接比较，填补了图结构收益量化的空白。
3. **扩展基准并升级特征表征**：新增C/C++系统（Bash、HDF、HDC、Chrome），将bag-of-words替换为128维Word2Vec标识符嵌入，提升跨语言泛化能力。
4. **揭示图有效性的系统属性边界**：定量验证连通性（average out-degree）与同配性（homophily）决定消息传递的收益区间，指出低同配/低连通系统可能更适合MLP。
5. **补充训练随机敏感度分析**：通过固定划分交叉多种子运行，证明部分模型的微小优势对训练种子敏感，提醒研究者避免过度解读单次中位数排名。

## 方法详解
- **任务形式化**：给定文件集 $\mathcal{F}$ 与固定模块集 $\mathcal{C}$，初始标注集 $L$（约5%，上下限30–200，且每模块至少1个样本）作为种子，目标预测 $U = \mathcal{F}\setminus L$ 的模块标签。转导设置下所有文件特征与图结构在训练期可见。
- **图构建**：文件为节点，静态依赖为有向边。依赖类型集 $\mathcal{R}$ 包含Call、Import、Extend、Use、Create、Implement等13类（Table 1），每类维护独立邻接矩阵 $A^{(r)}$。成员级依赖（方法/字段）聚合至文件级，重复边去重。
- **节点特征**：$x_i = [\text{Binary}(\text{FilePath})_i \parallel \text{Word2Vec}(T_i)]$。标识符经camelCase/snake_case切分、去除停用词与>90%文件共现词后，训练skip-gram Word2Vec（dim=128, window=5, min_count=5, vocab上限2000, 20 epoch）；文件路径构建二进制BoW（去除src/main/java等通用前缀）。
- **编码器设计**：
  - **GCN**：$h_i^{(k+1)} = \text{ReLU}\left(\sum_{r}\sum_{j \in \mathcal{N}_i^{r,\pi}} \frac{1}{\sqrt{d_i^r d_j^r}} W^{r,(k)} h_j^{(k)}\right)$，度归一化防止高连通文件主导聚合。
  - **GAT**：用注意力系数 $\alpha_{ij}^r$ 替代度权重，每关系4个头（64维）拼接后求和激活，增强对无用跨模块邻居的抑制能力。
  - **MLP**：单隐层256单位，仅使用 $x_i$，不聚合邻居，作为无图对照。
- **迭代自训练**：暖身100 epoch后，每轮用阈值 $\tau=0.95$ 选取高置信预测作为伪标签加入 $\mathcal{M}$，最多4轮×30 epoch；Adam优化器（lr=0.001）与参数跨轮次保持，交叉熵损失最小化。

## 实验与结果
- **数据集**：10个开源系统（Java: A.UML, C.Img, JabRef, Lucene, SH-3D, T.Mates；C/C++: Bash, HDF, HDC, Chrome），含已知GT映射与模块划分（Table 2）。
- **基线**：Python实现的NBA（Naive Bayes with CDA），沿用原始0.90置信阈值与自训练逻辑，扩展至C/C++。
- **评估协议**：Macro-F1（模块等权，暴露小模块性能）与Micro-F1（文件等权，反映整体准确率）；100次独立运行（不同划分+训练种子），Wilcoxon符号秩检验+Holm–Bonferroni校正。
- **主要数值结果**：
  - 三类神经网络均显著优于NBA；GAT系统级中位数Macro-F1 **83.5**、Micro-F1 **92.2**，在6/8系统上领先。
  - 小规模/稀疏系统（HDF、HDC、SH-3D）中MLP具竞争力；在Chrome（18,343文件）上GAT/GCN分别高出MLP **21.8/19.0 Macro-F1点**，且MLP有**10.4%**文件持续误分类，GNN仅**1.1%–1.2%**。
  - 多关系聚合在所有系统上显著优于合并单关系（Macro增益6.6–40.2点）；两阶层数对JabRef/Bash/Chrome有益，但对T.Mates/HDC有害。
  - 默认源→目标聚合在6个系统上优于反向聚合；反向聚合在Lucene/A.UML提升Macro-F1，且在Chrome上以牺牲Aggregate F1为代价将持续错误文件从204降至103。
  - 种子交叉实验表明SH-3D、T.Mates、HDC上的微小优势对种子敏感，仅Chrome优势跨种子稳定（均值+22.6点，95%区间[19.1, 26.6]）。

## 相关工作脉络
1. **吸引函数/Naive Bayes方法**（HuGMe, IRAttract, LSIAttract, NBA）：依赖被扁平化为实体特征，本文通过异构图消息传递显式建模拓扑关系。
2. **检索/推荐映射**（InMap）：无需预标注但依赖自然语言描述与人工交互；本文面向半监督全自动映射，仅需少量种子即可扩展至全量。
3. **LLM辅助映射与恢复**（GPT-4 CoT, ArchAgent, LLM embeddings）：侧重语义推理与架构发现；本文以轻量GNN实现可扩展的精确文件级映射，规避LLM推理成本与幻觉风险。
4. **无监督图架构恢复**（NEGAR, GAER）：模块集未知，依赖聚类发现；本文模块集已给定，转向半监督分类任务，评估协议与目标不同。
5. **作者前期GCN研究**（2025）：仅评估Java中等规模系统与单一GCN，未隔离图贡献；本文通过MLP对照、多关系设计与种子敏感性分析深化归因。

## 局限性与未来方向
- **外部有效性受限**：基准仅10个系统，Chrome是唯一工业级案例，结论难以直接外推至AI生成代码库或其他开发范式。
- **静态分析盲区**：Depends工具无法捕获运行时反射、函数指针、条件编译等动态依赖，错误/缺失边将直接影响消息传递。
- **粒度与转导限制**：以文件为最小单元，无法表达单文件多模块归属；图结构在训练期固定，新增文件或依赖变更需
