# 论文速读：When-Does-the-Dependency-Graph-Help-Code-to-Architecture-Map

## 一句话总结
本文研究如何将源代码文件映射到已知架构模块，将其形式化为**有向多关系依赖图上的半监督节点分类**任务；通过比较 GCN、GAT 与无图 MLP 基线在十个 Java / C/C++ 开源系统上的自训练映射效果，发现图结构收益在大规模、高连通系统（如 Chrome，18,343 文件）中尤为显著，且按依赖类型分别建模始终优于合并为单一边类型。

## 研究问题与动机
- **架构技术债务与一致性检查需求**：实现偏离预期模块化结构会产生架构技术债务；静态架构一致性检查（SACC）需要准确的文件‑模块映射，而手动维护成本高、常缺失或不完整。
- **现有 C2A 映射方法的局限**：传统吸引度/推荐方法（如 NBA、InMap）将依赖关系“展平”为节点特征，未显式建模系统间的拓扑关联；架构恢复方法（如 GAER）假设模块集未知，而映射任务中模块集由目标架构预先给定，两者评估与适用场景不同。
- **图神经网络收益尚不明确**：尽管图表示学习在架构恢复中表现良好，但在“给定模块集 + 少量标注”的映射设定下，依赖图究竟能带来多少增益、对哪些系统属性敏感，缺乏对照实验与系统性分析。
- **可复现性与鲁棒性疑问**：前期工作仅覆盖中等规模 Java 系统、仅使用 GCN、未隔离特征与图结构的贡献；本文扩展至 C/C++、引入 GAT 与 MLP 对照，并考察训练种子、层数、边方向、多关系 vs 单关系等设计选择的稳定性。

## 核心贡献（创新点）
1. **将 C2A 映射统一为图上的半监督节点分类框架**：以文件为节点、类型为边的多关系有向依赖图为输入，结合 Word2Vec 标识符与目录路径特征，通过迭代自训练将少量标注扩展到全量文件。
   - **与已有工作的本质区别**：不同于 NBA/InMap 等将依赖降维为节点特征的做法，本文保留完整拓扑结构并显式区分依赖类型，从而分离出“图消息传递”本身带来的映射增益。
2. **在相同特征与自训练流程下对比 GCN、GAT 与 MLP**：三个编码器共享节点特征、分类头与迭代学习循环，仅编码器结构不同，使实验能较为干净地评估依赖图贡献。
   - **与已有工作的本质区别**：以往研究多只比较图模型之间或仅报告单一模型效果；本文通过 MLP 无图基线提供反事实对照，量化图结构相对于纯词法特征的增量。
3. **系统性地分析图收益的系统依赖性**：发现连接度（average degree）与同质性（homophily）可解释部分性能差异，并在大规模系统 Chrome 上观察到图模型显著降低持续误分类文件比例。
   - **与已有工作的本质区别**：此前研究多为平均指标报告；本文进一步从“文件级持续错误分布”角度揭示图模型在难样本上的稳定性优势。
4. **消融多关系建模、层数与边方向**：证明按依赖类型分别学习变换始终优于合并为单一边；层数与传播方向的效果高度依赖系统结构，不存在普适最优配置。
   - **与已有工作的本质区别**：多数图架构工作默认使用单关系无向图；本文在软件图谱上验证多关系必要性，并首次在该任务上对比前向/反向/无向聚合。
5. **揭示训练种子敏感性并给出稳健结论边界**：交叉种子实验表明部分模型的微弱优势随随机种子翻转，但 Chrome 等大系统上的图收益保持稳健。
   - **与已有工作的本质区别**：前人工作通常仅报告单次或少数几次运行结果；本文通过 100 次随机划分 + 种子交叉分析，明确区分“统计显著但种子敏感”与“稳健大增益”。

## 方法详解
- **问题形式化**：给定文件集 $\mathcal{F}$、固定架构模块集 $\mathcal{C}$、已标注子集 $L$，目标为未标注文件 $U=\mathcal{F}\setminus L$ 分配模块标签 $y_i\in\mathcal{C}$；训练时所有文件的节点特征与图结构可见（转录设定），仅模块标签受限。
- **图构建**：
  - 节点特征 $x_i = [\mathrm{Binary}(\mathrm{FilePath})_i \;\|\; \mathrm{Word2Vec}(T_i)]$，其中标识符经 camelCase/PascalCase/snake_case 切分、去停用词与高频词后训练 128 维 skip‑gram 向量，文档级取均值并 $\ell_2$ 归一化；路径做二进制词袋（去除公共前缀与 `src/main/java` 等通用词）。
  - 边为 Depends 工具提取的静态依赖，按类型分为 13 种（Annotation、Call、Cast、Contain、Create、Extend、Implement、Import、Parameter、Return、Throw、Use 等），每种类型维护独立邻接矩阵 $A^{(r)}$，方向保留（有向）。
- **编码器**（三者输入均为 $h_i^{(0)}=x_i$）：
  - **GCN**：$h_i^{(k+1)}=\mathrm{ReLU}\!\left(\sum_{r}\sum_{j\in\mathcal{N}_i^{r,\pi}}\frac{1}{\sqrt{d_i^r d_j^r}}W^{r,(k)}h_j^{(k)}\right)$，按关系与层学习变换，Degree 归一化防止高连节点主导。
  - **GAT**：$h_i^{(k+1)}=\mathrm{ReLU}\!\left(\sum_{r}\sum_{j\in\mathcal{N}_i^{r,\pi}}\alpha_{ij}^r W^{r,(k)}h_j^{(k)}\right)$，每关系 4 头注意力 concat 后求和；能自适应降低无关跨模块邻居权重。
  - **MLP**：单层隐藏层（256 单元）$h_i^{(k+1)}=\mathrm{ReLU}(W^{(k)}h_i^{(k)}+b^{(k)})$，仅用节点自身词法特征，不与邻居交互。
- **迭代自训练流程**：初始标注集占 5%（30–200 个文件，且每模块至少 1 个样本）；先 warm‑up 100 轮，随后最多 4 轮自训练，每轮 30 轮；置信度阈值 $\tau=0.95$，仅将高置信预测提升为伪标签；训练保留 Adam 状态，损失为全批量交叉熵。

## 实验与结果
- **数据集**：10 个开源系统（6 Java：A.UML、C.Img、JabRef、Lucene、SH‑3D、T.Mates；4 C/C++：Bash、HDF、HDC、Chrome），文件数 153–18,343，模块数 6–69，图边数 1,117–284,435，平均出度 4.2–23.4，同质性 $H$ 0.34–0.68。
- **评估基线**：Naive Bayes 映射器 NBA（Python 重实现 + C/C++ 扩展，沿用原 0.90 阈值与迭代流程）；内部对照：MLP、GCN、GAT。
- **主要结果（100 次运行中位数）**：
  - 所有神经网络方法在全部 10 个系统上均显著优于 NBA（宏/微 F1）。
  - **GAT 平均性能最佳**：系统级中位数宏 F1 = **83.5**，微 F1 = **92.2**；在 6/10 系统宏 F1、8/10 系统微 F1 上领先。
  - **MLP 在小型/低连通系统具竞争力或更优**：A.UML、SH‑3D、HDF、HDC 宏 F1 领先或接近；HDF 上 MLP 显著优于 GAT。
  - **Chrome 规模效应显著**：GAT/GCN 较 MLP 分别提升宏 F1 **+21.8 / +19.0** 点、微 F1 **+17.1 / +16.1** 点；MLP 持续误分类文件占比 10.4%，GCN 1.2%，GAT 1.1%。
  - 微 F1 整体稳定（7/10 系统 IQR<6），宏 F1 在小模块占比高的系统（如 HDC）波动更大。
- **消融关键数字**：
  - **多关系 vs 单关系**：GAT 宏 F1 提升 6.6–40.2 点，GCN 8.1–32.7 点，**所有系统、双指标均显著**。
  - **层数**：2 层 GAT 在 JabRef/T.Mates/Bash/Chrome 宏 F1 显著优于 1 层；2 层 GCN 在 JabRef/Bash 双指标显著优于 1 层。
  - **边方向**：默认前向（source‑to‑target）在 6/10 系统宏 F1 显著优于反向；反向在 A.UML/Lucene 宏 F1 提升 1.5/4.2 点。
  - **种子敏感性**：交叉种子实验显示 SH‑3D、T.Mates、HDC 上部分微弱优势随种子翻转；Chrome 上 GAT vs MLP 优势在 50 次 split‑seed 组合中全部显著（均值 +22.6，95% CI [19.1, 26.6]）。

## 相关工作脉络
- **NBA / HuGMe / IRAttract 等吸引度方法**：依赖关系被编码为节点级文本/统计特征，未保留图拓扑；本文将其置于相同自训练循环下作为非图统计基线，量化拓扑增益。
- **InMap**：基于检索的交互式推荐，无需训练集但依赖自然语言模块描述；本文聚焦完全自动化的半监督分类，不要求人工描述且能在小规模标注下全量展开。
- **LLM 映射/恢复（GPT‑4 提示、ArchAgent 等）**：利用预训练语义捕捉设计 cue；本文走轻量图表示路线，强调显式依赖类型与消息传递的结构归纳偏置，计算成本更低、可解释性更强。
- **架构恢复图方法（NEGAR、GAER）**：模块集由聚类自动生成，属无监督场景；本文模块集固定，任务为有监督/半监督分类，评估可直接对照已知 GT，避免预训练暴露偏差。
- **早期 GCN‑C2A 工作（作者前期 ICSC‑A 2025）**：仅使用 GCN、仅限 Java 中等规模系统、无 MLP 对照、标识符用 bag‑of‑words；本文扩展语言、加入 GAT/MLP、改用 Word2Vec、系统分析设计敏感性与种子稳定性。

## 局限性与未来方向
- **规模与语言覆盖有限**：工业级系统仅 Chrome 一个，无法断定图收益随规模单调增长；未涵盖 Python、Go 等现代语言及 AI 生成代码主导的项目。
- **静态依赖的缺失与噪声**：反射、函数指针、条件编译、宏展开等运行时依赖未被捕获；错误边会直接污染消息传递。
- **版本对齐风险**：部分 GT 映射建立早于所用源码版本，构建配置差异可能导致文件集合不一致。
- **单标签假设**：文件只能归属单一模块，难以处理跨模块关注点或历史漂移产生的模糊归属。
- **编码器容量未完全对齐**：GAT/GCN 参数量多于 MLP，多关系配置也引入额外参数，图收益部分可能混入容量优势。
- **未来方向**：① 在关系类型上增加注意力加权，替代当前的等权求和；② 引入目录层级、类成员等更细粒度架构信号；③ 分离标识符特征与路径特征，厘清 MLP 信号来源及其与图信息的重叠程度。

## 研究启发与可借鉴点
- **特征/流程对齐的对照设计**：固定节点特征、分类头与自训练循环，仅更换编码器，可干净剥离“图结构贡献”，该方法论值得推广到其他图应用的主客观增益评估。
- **文件级持续错误分布作为补充指标**：除了平均 F1，统计“跨多次运行始终误分类”的文件比例，能更好反映工程落地中的鲁棒性与难样本覆盖。
- **多关系独立变换优于合并**：在软件依赖图中，调用、继承、导入等不同关系承载差异化的模块归属线索，分开建模可显著提升性能；该结论可迁移到多关系软件图的其他下游任务。
- **种子敏感性报告应成为常态**：软件图任务的模块分布极度不均衡，微小种子变化可导致排名翻转；未来工作应在论文中显式报告 split‑seed 交叉区间，避免过度解读微弱优势。
- **方向性聚合的工程权衡**：前向聚合（聚合依赖者）通常更优，但反向在某些系统上能减少持久错误；可根据具体目标（整体 F1 vs 错误尾部）灵活选择。

## 关键术语表
- **Code-to-Architecture Mapping（C2A 映射）**：将源代码文件自动分配到目标架构模块的任务，是静态架构一致性检查的前置步骤。
- **Semi-supervised Node Classification（半监督节点分类）**：在图结构中仅对少量节点提供标签，通过图消息传递与伪标签自训练推断其余节点类别。
- **Multi-relational Dependency Graph（多关系依赖图）**：以文件为节点、以依赖类型分别为边的异构图，不同类型保留独立邻接矩阵。
- **Homophily（同质性）**：图中两端节点属于同一模块的边占比；高同质性通常利于消息传递，低同质性可能引入噪声。
- **Iterative Self-training（迭代自训练）**：在伪标签置信度超过阈值时逐步将未标注节点纳入训练集并重新训练，直至新增饱和。
- **Macro / Micro F1（宏/微 F1）**：宏 F1 对每个模块同等加权，适合评估小模块性能；微 F1 对每个文件同等加权，反映整体正确率。
- **Forward / Reverse / Undirected Aggregation（前向/反向/无向聚合）**：前向聚合从“依赖该文件的文件”传播，反向从“该文件依赖的文件”传播，无向合并两者。
- **Persistent Misclassification（持续误分类）**：在多次随机划分与种子运行中始终预测错误的文件，用于衡量模型的尾部稳定性。

## 可复现要素
- **数据集**：十个开源系统（A.UML、C.Img、JabRef、Lucene、SH‑3D、T.Mates、Bash、HDF、HDC、Chrome），GT 映射来源于 s4rdm3x GitHub 仓库、Garcia 等人整理版本、SARIF 基准包；**数据获取受原始映射提供方限制，需按仓库说明申请**。
- **代码/权重**：完整复现包（源码、实验分割、结果、环境配置）已开源至 `https://github.com/sse-lnu/GCN-SAEroCon25`，接受后将归档于 Zenodo 并附 DOI。
- **关键超参**：隐藏层 256 维；GCN/GAT 均为 2 层；GAT 每关系 4 头、每头 64 维；Dropout 0.01（仅 GNN）；Adam lr=0.001；Warm-up 100 轮，自训练每轮 30 轮、最多 4 轮；置信度阈值 0.95；初始标注 5%（30–200 文件且每模块至少 1 个）；随机种子 42+split_id；Word2Vec 窗口 5、负采样次数 5、词表上限 2,000、最小词频 5、20 轮；100 次固定分割复现实验。
