# 论文速读：WHEN-NOT-HOW-MUCH-EVALUATING-TIME-SERIES-FOUNDATION-MODELS-O

## 一句话总结
本文针对稀疏时间序列的**窗口内事件排序（within-window event ranking）**任务，提出了一套评估协议，通过对比TSFM的原始点预测、冻结骨干上的监督线性探针、原始上下文学习器及随机化对照，揭示了当前主流TSFM点预测在该任务上增益极其有限，而轻量级事件探针是更有效的利用方式。

## 研究问题与动机
1.  **任务缺失**：现有的TSFM基准（如GIFT-Eval, BOOM）主要评估未来数值（均值/中位数）的预测精度，但稀疏时间序列（如间歇性需求、罕见病病例）中的决策往往只关心**事件是否在某个未来时段发生**，而非发生多少。
2.  **输出鸿沟**：TSFM发布的点预测通常是对预测分布的中位数或均值聚合。对于高度偏斜的稀疏数据，中位数在事件概率低于50%时会输出为0，导致完全无法区分不同位置发生事件的概率差异。
3.  **表征价值未验证**：虽然已有研究使用TSFM表征进行下游分类，但在事件排序任务上，冻结的预训练表征是否比原始上下文（raw context）或随机初始化表征更具优势，尚不明确。
4.  **缺乏系统评估**：缺少一个能同时揭示“输出级性能”、“表示级潜力”和“预训练贡献”的系统性评测框架。

## 核心贡献（创新点）
1.  **提出窗口内事件排序任务与协议**：形式化定义稀疏序列的排序任务，构建5个高稀疏度公共数据集，并提出基于**机会校正（chance-corrected）**的AP skill与AUC skill指标。
2.  **输出级评估揭示有限增益**：系统评估12个TSFM，发现其点预测相比简单无训练参考的提升极小（AP skill最高仅+0.031）。
3.  **表示级评估确立探针优势**：证明在冻结骨干上训练的轻量级线性事件探针，在绝大多数情况下显著优于主干模型自身的点预测（29/30对比中获胜）。
4.  **提供多重对照以严谨归因**：引入**原始上下文学习器（Raw-context learner）**和**随机化骨干网络（Randomized backbone）**作为对照，分离出“使用何种特征”、“使用何种学习器”以及“预训练权重本身”的贡献。

## 方法详解
1.  **评估协议三问（Q1-Q3）**：
    *   **Q1 (Output-level)**：TSFM点预测 vs. 免训练参考（季节性剖面、趋势斜坡）。
    *   **Q2 (Representation-level)**：冻结骨干上的线性探针 vs. 点预测；线性探针 vs. 原始上下文的Logistic回归 vs. 原始上下文的LightGBM。
    *   **Q3 (Pretraining)**：预训练骨干的探针 vs. 随机初始化同名骨干的探针。
2.  **模型与数据**：
    *   **TSFMs**：评估Chronos-2, TimesFM-2.5/3, Moirai系列等12个模型；对其中6个（Chronos-2, Chronos-Bolt, Sundial, TimeMoE, Timer, Toto-2.0）提取对齐预测窗口的冻结表征进行探针实验。
    *   **数据集**：Amazon购买、Favorita销售、M5销售、NYC出租车、Wikipedia网页流量，共5个，零值比例45%-87%。
3.  **评估指标**：
    *   **AP Skill / AUC Skill**：在每个窗口内独立计算AP/AUC，并减去其随机排列期望值后归一化。$S^{AP} = (AP - AP^0) / (1 - AP^0)$。这确保随机排序得分为0，完美排序得分为1。
4.  **探针训练**：
    *   使用事件标签（$y_{w,h} = 1$ if activity > 0）训练线性层或LightGBM分类器。
    *   训练数据限制在10万窗口，防止过拟合。
    *   随机化骨干保持相同架构、预处理和提取路径，仅权重替换为默认初始化。

## 实验与结果
1.  **Q1结果（点预测有限）**：所有TSFM的点预测相比免训练参考，AP skill提升不超过**0.031**。在AUC skill上，中位数TSFM在5个数据集上均**低于**参考。
2.  **Q2结果（探针显著优于点预测）**：
    *   线性探针在**29/30**个骨干-数据集对中优于其主干的点预测。
    *   在NYC taxi和Web traffic上，探针普遍优于原始上下文的Logistic回归和LightGBM。
    *   在Favorita和Amazon上，最强探针接近或略超原始上下文LightGBM；在Web traffic上，所有探针大幅落后于LightGBM。
3.  **Q3结果（预训练价值因模型而异）**：
    *   在Chronos-2, Chronos-Bolt, Sundial, TimeMoE, Toto-2.0上，预训练特征在**5/6**骨干中均优于随机特征。
    *   **Timer是个反例**：在其随机化版本上训练的探针在Favorita, M5, Web traffic上**超过**了预训练版本。诊断表明Timer预训练表征在捕获近期事件**模式**方面甚至弱于随机初始化。
4.  **关键数字**：
    *   最佳探针（如Chronos-2 on Favorita, AP skill=0.193）显著优于其点预测（0.116）和免训练参考（0.103）。
    *   预训练对Timer的优势逆转幅度最大（Favorita上随机化探针AP skill达0.172，预训练仅0.135）。

## 相关工作脉络
1.  **TSFM基准测试**：GIFT-Eval和BOOM评估TSFM的零样本数值预测能力，但未聚焦稀疏事件排序。本文补充了这一评测缺口。
2.  **稀疏时间序列建模**：Hurdle/ZI模型、Croston's method、TSB方法等显式建模发生率和幅度，但本文的评估对象是端到端基础模型，关注其内部表征是否隐含此类信息。
3.  **TSFM表征探针**：先前工作（如Auer et al., 2025; Feofanov et al., 2026）使用探针分析TSFM用于分类的表征。本文的独特之处在于使用**与预测目标相同的事件标签**，并直接与**模型自身发布点预测**对比。
4.  **探针控制实验**：借鉴NLP领域控制任务思想（Hewitt & Liang, 2019），引入随机化骨干对照，指出仅有探针分数不足以证明预训练价值，因为随机特征也可能被有效利用。

## 局限性与未来方向
1.  **数据范围**：仅评估5个公开数据集，且所有评估的窗口目标必须同时包含事件和零（即非全活或非全零），无法评估模型识别完全静默期的能力。
2.  **零值的歧义**：数据集中的零可能代表真正的零活动，也可能是缺失值（如网页流量数据中68%的零标签是缺失值）。
3.  **探针灵活性**：仅探索了线性探针和GBM探针。更复杂的微调策略或不同架构的头部可能带来更大提升。
4.  **预训练数据重叠**：部分TSFM（如TimesFM）的训练数据可能包含测试数据源，可能高估预训练优势（论文已通过披露排除的配对对比缓解此问题）。

## 研究启发与可借鉴点
1.  **评估范式可迁移**：这套“输出-表征-对照”三层评估协议非常适合用于评估其他领域基础模型（如LLM, LVM）在特定子任务（如异常检测、定位任务）上的实际效用。
2.  **关注输出聚合方式**：论文发现将分位数平均替代中位数可提升排序能力。这启发我们在设计TSFM应用时，不应直接使用模型默认点预测，而应尝试从分布中提取更适合下游任务（如分类、排序）的聚合统计量。
3.  **警惕“最弱模型”陷阱**：Timer的结果提醒我们，基础模型的预训练目标可能与下游任务（如稀疏事件排序）所需表征存在错位，预训练并非万能。随机初始化+充足下游数据在某些情况下可能更优。
4.  **结合简单强基线**：原始上下文上的LightGBM表现强劲，尤其是对Web traffic这类数据。这表明在处理稀疏事件排序时，精心设计的数据工程（特征构造）和强监督模型仍是重要基线，不应被忽视。

## 关键术语表
**Within-window event ranking**：在单个预测窗口内，根据历史上下文对未来的各时间点按事件发生概率进行排序的任务。
**AP Skill / AUC Skill**：经过机会校正（减去随机期望）并归一化后的平均精度（AP）和曲线下面积（AUC）指标，用于衡量窗口内排序质量。
**Linear Probe**：在冻结的基础模型表征上，训练一个轻量级线性分类器来预测下游任务标签，以评估表征的信息含量。
**Randomized Backbone**：使用与预训练模型相同架构但权重为随机初始化的模型，用于作为对照以量化预训练带来的特有优势。
**Training-free Reference**：无需在任务标签上训练的简单基线，如基于历史数据的季节性事件率剖面或趋势斜坡。
**Sparse Event**：在大量时间步中仅零星出现非零值的事件，如间歇性需求、稀有故障等。
