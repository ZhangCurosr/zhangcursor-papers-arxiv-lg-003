# 论文速读：When-the-Right-Answer-Is-Missing-An-Arithmetic-Dependent-Rej

## 一句话总结
论文发现 typed decision 模型 Jev 在算术任务上存在"正确答案缺失时的拒绝瓶颈"：虽有明确拒绝选项（NONE），但答案存在时准确率高达 99%，答案缺失时正确拒绝率仅 7%；作者提出基于分数的阈值校准方法，无需重训练或额外推理即可将拒绝准确率从 7% 提升至 79%。

## 研究问题与动机
- **核心问题**：当候选选项集中不包含正确答案时，Jev 能否可靠地选择拒绝？现有工作假设推荐添加 NONE 选项即可解决，但作者发现这存在严重的算术依赖性拒绝瓶颈。
- **现有方法不足**：TypeSafe 官方推荐在候选集中包含 "other" 或 "noneof-the-above" 选项以支持拒绝，但未评估该方案在算术计算场景下的可靠性。
- **实践动机**：在支付对账、库存更新等真实工作流中，候选集可能全部无效，可靠的拒绝机制至关重要。
- **现象矛盾**：原生 Boolean 验证在相同算术案例上准确率达 99%，而 Menu Choice 的拒绝率仅 7%，说明问题不在计算能力而在决策接口。

## 核心贡献（创新点）
- **发现算术依赖拒绝瓶颈**：Jev 在算术任务上呈现强烈的选择-拒绝鸿沟（99% vs 7%），该差距跨越数值量级、运算深度、上下文形式和拒绝标签，揭示了高选择准确率掩盖的可靠性盲区。
- **解耦计算与接口效应**：通过三组对照实验（Menu Choice、Candidate T/F Choice、Native Boolean）证明拒绝失败源于决策接口类型而非单纯计算难度或分解方式。
- **揭示分数保留的拒绝信号**：分析输出概率分布发现，即使选择错误，答案缺失案例仍倾向于分配更高的 NONE 概率，说明模型内部已具备区分能力。
- **提出零成本阈值校准方案**：在开发集上选择决策阈值后，无需重训练或额外推理，将算术拒绝准确率从 7% 提升至 79%，同时保持 97% 的选择准确率。

## 方法详解
- **三种决策形式**：
  - **Menu Choice**：从 {A, B, C, NONE} 中选择，按 TypeSafe 推荐 NONE 表示无有效候选。
  - **Candidate T/F Choice**：对每个候选分别询问"是否正确"，使用 categorical true/false 输出，三个问题打包为一个请求。
  - **Native Boolean**：与 T/F Choice 相同问题但改用 Boolean 类型，仅 type 字段不同。
- **配对评估框架**：每个问题生成一对菜单（答案存在/缺失），共享相同事实与错误选项，仅覆盖度 c ∈ {0,1} 不同。
- **准确率度量**：菜单层面 $A_{h,c} = \frac{1}{n}\sum \mathbf{1}[\hat{z}_{jc}^h = z_{jc}]$，候选验证需三个标签全对。
- **阈值校准机制**：
  - 菜单拒绝：若 $p_\emptyset \geq \tau$ 则拒绝，否则 argmax 选择最高概率候选。
  - 候选验证：对每个 truth score $s_i$，判断 $\hat{z}_i = \mathbf{1}[s_i \geq \tau]$。
  - 校准在独立开发集（20 对案例）上搜索 $\tau \in [0,1]$，目标为两种覆盖条件的平均准确率。

## 实验与结果
- **数据集**：两步算术 $(a+b-c)$、数值查找、购买总额 $(qp+s)$、库存更新、退款策略、时间计算、容量取整等 15 个任务族，每任务 20–100 对案例。
- **评估基线**：Jev（Menu/T-F/Boolean）、Qwen3.5-9B（reasoning）作为生成式控制。
- **主要结果**：
  - **Menu Choice**：算术任务答案存在 99%、缺失 7%（差距 92 点）；购买总额 94% vs 24%（差距 70 点）。
  - **Native Boolean**：算术答案缺失准确率达 99%，证明模型具备验证能力。
  - **Qwen3.5-9B**：算术和购买菜单准确率达 100%/100%，证明候选构造本身不阻碍拒绝。
  - **运算深度**：仅 2 次运算 Menu 拒绝即降至 4%，Boolean 保持 92%。
  - **阈值校准**：$\tau=0.03$ 使算术拒绝从 7%→79%，选择准确率 99%→97%；$\tau=0.74$ 使 T/F 精确匹配从 27%→90%。
- **结论**：拒绝失败是接口相关而非能力相关，分数校准可在零额外成本下显著修复。

## 相关工作脉络
- **LLM 弃权/拒绝研究**（Wen et al., 2025; Madhusudhan et al., 2025; Kirichenko et al., 2025）：关注生成式 LLM 在不可答问题上的 abstention 能力；本文聚焦 typed decision API 的拒绝行为，揭示算术依赖的特定瓶颈。
- **Jev 接口行为研究**（TypeSafe AI, 2026b; Sun & Xu, 2026; Zhang et al., 2026）：TypeSafe 文档数学局限、Sun & Xu 研究选项名-标准冲突；本文通过配对控制精确隔离算术拒绝缺口。
- **不确定性拒绝**（Tomani et al., 2024）：基于 uncertainty 的 abstention；本文利用已返回的概率分数进行阈值校准，无需引入额外不确定性估计。
- **最少错误选项选择**（Wang et al., 2025）：发现 LLM 可能选"最不错误的选项"；本文表明 Jev 在算术缺失场景更可能是接受错误候选而非主动选"次优"。
- **Domain-dependent N/A 表现**（Tam et al., 2025）：发现 none-of-the-above 表现因领域而异；本文量化算术任务是最严重退化场景之一。

## 局限性与未来方向
- **黑盒评估局限**：仅通过托管 API 观测输入输出，无法访问模型权重或内部激活，不能直接定位拒绝瓶颈的内部机制。
- **合成数据局限**：实验使用合成数值/符号记录，未测试真实检索场景下的候选生成质量。
- **任务覆盖有限**：仅评估 15 个任务族，算术相关任务表现差而符号/查找类任务正常，泛化性待验证。
- **未来方向**：真实检索工作流中的端到端评估、跨任务校准、训练层面引入可靠拒绝能力。

## 研究启发与可借鉴点
- **阈值校准作为即插即用修复**：无需修改模型架构或重训练，仅利用输出分数分布偏移即可显著提升拒绝准确率，可作为 typed decision 系统部署前的标准化后处理步骤。
- **配对评估框架的通用价值**：答案存在/缺失的配对设计消除了任务分布差异，能精准暴露接口相关的失败模式，建议推广至其他 decision model 评估。
- **分数分析揭示隐藏能力**：AUC 分析表明 T/F Choice 的分数排序（AUC=0.985）远优于决策本身（88/200），提示评估时应同时报告分数判别力而不仅看 accuracy。
- **接口类型作为消融变量**：通过仅修改 type 字段（Choice→Boolean）控制单一变量，有效解耦了计算、分解和接口效应，是 API 对比实验的设计典范。
- **与团队方向结合机会**：若团队涉及决策型 AI 系统或 RAG 后处理，可将阈值校准集成至候选过滤流水线；配对评估框架也可用于检测自身系统的拒绝盲区。

## 关键术语表
- **Typed Decision Model**：接受状态描述和预定义输出标准、直接返回结构化判断（而非自回归生成）的决策模型，如 Jev。
- **Arithmetic-Dependent Rejection Bottleneck**：模型在算术计算任务上能正确选择答案，但在答案缺失时无法可靠拒绝的现象。
- **Menu Choice**：从预设候选集（含 NONE）中选择最优选项的 categorical 决策接口。
- **Candidate T/F Choice**：对每个候选单独询问真假的分类决策形式，本题中作为 ablation 而非原生接口。
- **Native Boolean**：直接使用 Boolean 类型接口验证候选正确性，本题关键对照组显示其拒绝性能显著优于 Menu。
- **Threshold Calibration**：在独立开发集上搜索决策概率阈值，以平衡选择准确率与拒绝准确率的后处理方法。
- **Paired Coverage Gap**：同一问题在答案存在（c=1）与缺失（c=0）两种覆盖条件下的准确率差值，用于量化拒绝失败程度。
- **AUC（Area Under ROC Curve）**：衡量模型分数对正确/错误候选排序能力指标，AUC=0.5 为随机，1.0 为完美排序。
